## Confirmed campaign changes

### Dynamic unit generation

Pacific Strike now connects `[DynamicUnitGeneration] Taskforce2RosterFile=enemy_theater_roster.ini`. Its new roster separates major flagships, persistent units, reusable units, aircraft/helicopters, nations, and formations. All 14 tactical mission files contain dynamic replacement slots—94 slots total, ranging from 2 in `09 Shadows off Palawan.ini` to 16 in `10 Vengeance at Luzon.ini`. Selected timeline nodes set `DynamicGenerationPersistent=True`.

The active assembly contains `SeapowerUI.ViewModels.DynamicUnitGeneration`, assignment/snapshot/theater state, reusable and persistent paths, formation rebuilding, saved seeded assignments, spawn-zone support, filters, and Situation records. This confirms an implemented subsystem, not merely commented data.

### Loadout and stores rules

New active fields/methods include:

- `EnableStoresEditor`
- `MaxLoadoutYear`
- `TaskForceModeLoadoutYearReward`
- `TaskForceModeUnitYearReward`
- unit/loadout-year readers and unlock checks
- authored roster price and store/loadout accounting paths.

Pacific Strike sets `EnableStoresEditor=False`, `MaxLoadoutYear=1984`, and grants loadout year 1988 at its former named-loadout milestone. Its stock comments state that named locked loadouts are reward-gated, date-gated loadouts use the year ceiling, explicitly roster-priced loadouts ignore the ceiling, and disabling the date-limit difficulty rule removes both ceilings.

### Difficulty and commander setup

Campaign difficulty values are presented as sliders and can be customized in pre-launch setup. Commander setup also moved into pre-launch. Unrestricted Mode commander nationality was repaired in #365.

### Economy topology

Pacific Strike's authored mission completion points, cap increases, and rewarded-unit rows match the #363 version. The economy **structure** remains a valid example; its numerical unit-price analysis does not.

## Point formula and price invalidation

Reflection of `SeaPower.PointValueTuning` confirms:

- `FORMULA_VERSION`: 134 → 140;
- `HandAuthoredScaleBridge`: remains 10;
- new ammunition/store pricing constants and warload-related tuning;
- existing role, sensor, weapon, survivability, hosting, and mobility pricing remains implementation-driven.

The changelog additionally reports fixes for missing default optional weapons, weapon swaps, manually set price scaling, and stores-editor pricing. Consequently:

- do not balance #366 from a formula-134 cache;
- do not assume a #363 authored override displays identically until tested;
- regenerate prices with the intended roster, difficulty, loadout, date limit, and stores settings;
- retain old numbers only as labeled historical evidence.

## Mission and narrative authoring changes

### Air Operations

Build #366 promotes legacy `CivilianRouteN` data into the Mission Editor's Air Operations tab. The changelog confirms route visualization/scheduling, player/neutral/red support, per-waypoint speed/altitude/sensor/ROE/attack/refuel/RTB orders, unit-relative waypoints, fuel-range validation, initial disable state, and trigger enable/disable/reactivate actions.

The active `SeaPower.CivilianRoute` class gained editor-authored state, operation keys, squadron name, waypoint definitions, pending-flight-deck tracking, and explicit enable/disable/reactivate methods. Existing legacy files remain supported. No shipped file was found that cleanly demonstrates every new serialized waypoint/action token, so editor-generated output must be captured before the field reference becomes more granular.

### Briefings and EMCON

Build #364 unified briefing previews, fixed automatic briefing-folder creation, and added rich-text generation of `BriefingText_xy.xml`. Force EMCON can now be set in the editor and controlled through system trigger actions.

### Doctrine/ROE

The new Standing Orders system supports global, formation, and unit levels; formation/unit rules can override global rules and are saved inside missions. Player aircraft RTB/launch-on-weapons-hold behavior and surface missile auto-attack controls changed. Existing scenarios should be checked for unintended autonomous engagement or emissions.

## Persistence fixes requiring regression

Build #364 reports fixes for:

- loading a campaign save only once per session;
- mission score;
- landing aircraft destruction on reload;
- no-magazine ammunition display;
- saved player victory state;
- survivors aboard aircraft;
- map layers;
- wake bubbles.

These fixes strengthen the intended persistence model but invalidate blanket reliance on #363 failure/success behavior in those exact cases.

## Unit database delta relevant to authors

Added definition files include:

- KC-10 tanker; placeholder KC-135 files removed;
- N22 Nomad and two Searchmaster derivatives;
- S-2E;
- Hatsuyuki destroyer;
- Bunker Hill cruiser;
- Spruance VLS destroyer;
- improved Victor III submarine;
- SS-1C Scud-B TEL and missile;
- several new weapons/stores, including RIM-66H, RUM-139A, Mark 81, and Mark XI depth bomb.

Removed definition files include the placeholder Tu-16N tanker. Many existing aircraft, vessel, land-unit, ammunition, sensor, and weapon files changed. This broad change is partly due to new common metadata and should not be interpreted as every unit receiving a major capability change.

Explicitly relevant corrections include ship-loadout restoration in #365/#366, California date-based Harpoons, Sturgeon service dates, Los Angeles speed/ammunition, submarine endurance, Forrestal default Phoenix load, F-111 range, APY-1 surface-detection removal, sonobuoy reductions, and aerial-refueling normalization.

Build #364 also fixes summer snow in the Falklands terrain and adds an Argentina mast flag. Both are useful beyond the original project because they demonstrate that map climate and displayed nationality can change independently of base-platform files.
